# AGENTS.md

This file provides guidance to coding agents (Claude Code, OpenCode, ...) working with code in this repository.

## What this is

NetSuite SDF customization for the Multicenter/Multicard module. TypeScript source compiles to AMD (SuiteScript 2.1) and deploys via the SuiteCloud CLI. Pragmatic Clean Architecture (4 layers) with a strict **1-RESTlet-per-use-case** convention.

Reference docs (read on demand — not duplicated here):
- `README.md` — architecture, RESTlet naming convention, build workflow.
- `MANUAL.md` — endpoint reference, request/response shapes, TBA/OAuth 1.0 auth.
- `docs/arquitectura/resumen-arquitectura.md` — layer-by-layer architecture explanation (Spanish).
- `docs/arquitectura/patron-dominio.md` — how to model the domain layer.
- `.claude/agents/architect/agent.md` — full architecture guide (the `architect` agent); this file is the source of truth for rules.

## Commands

Package manager: **pnpm 9.x** (Node >= 22). Run everything from the repo root.

```bash
pnpm build        # format TS → tsc (AMD) → inject NetSuite headers → format JS
pnpm test         # jest (runs against COMPILED JS — see gotchas)
pnpm lint         # biome check, no fixes
pnpm lint:fix     # biome safe auto-fix
pnpm watch        # tsc -w ONLY (no format, no header injection)
pnpm run deploy   # build → suitecloud project:deploy (use `run`: pnpm 9.x reserves `deploy`)
```

Pre-deploy gate (all three green): `pnpm build && pnpm test && pnpm lint`.

Run a single test (build first):
```bash
pnpm build && pnpm test -- __test__/installment/installment.domain.test.js
pnpm build && pnpm test -- -t "French amortization"
```

## Critical gotchas

1. **IMPORTANT: tests run against the compiled JS, not the TS source.** Specs import from the `SuiteScripts/multicard-api/...` alias (from `@oracle/suitecloud-unit-testing`), which resolves to `src/FileCabinet/SuiteScripts/`. **You must run `pnpm build` before `pnpm test`** or you test stale/missing output.
2. **IMPORTANT: `tsc` strips file-level JSDoc** when emitting AMD. `scripts/inject-headers.js` re-injects the `@NApiVersion / @NScriptType / @NModuleScope` header from the `.ts` into the `.js`. Every deployable script **must start with that JSDoc header** or NetSuite rejects the deploy. `pnpm watch` does NOT run this step.
3. **NEVER edit `src/FileCabinet/SuiteScripts/` by hand** — it is generated by `pnpm build` and `prebuild` wipes it on every run.
4. `pnpm watch` does not format: a line over `lineWidth: 100` won't be auto-split. `tsc` emits no JS if there is a type error (`noEmitOnError`).

## Architecture — the dependency rule

Per feature under `src/TypeScripts/multicard-api/features/<feature>/`:

```
domain/       entities (classes with props + behavior) + pure functions. ZERO N/* imports.
usecase/      use cases + ports/ (the IXxxRepository interface is declared HERE).
repository/   NetSuite adapter. The ONLY layer that imports N/search, N/record, N/log.
```

Plus, at `src/TypeScripts/multicard-api/`: `suitescript/restlet/` (driving adapters + composition roots, HTTP entry points) and `shared/` (`ApiResponse`, `CUSTOMER_TYPE`, status).

Dependencies point inward (`restlet → usecase → domain`); the repository implements a port the use case declares. Concrete rules:
- **Ports live with the use case, not the repository.** A repo does `implements ICustomerRepository`, where that interface is under `usecase/ports/`. Cross-feature use is allowed (the `installment` use case consumes `customer`'s port).
- **NetSuite custom-field IDs (`custentity_...`) live ONLY in the repository**, in a `FIELDS` const next to a single `toDomain` mapper. Domain and use case never see a NetSuite field name.
- **Composition root (restlet):** instantiate the repository once at module scope, parse the request, `new` the use case per request, return `JSON.stringify(useCase.execute(...))`. Example: `suitescript/restlet/mc_rl_mcard_get_customer.ts`.

## Conventions

- **RESTlets:** file `mc_rl_mcard_<verb_noun>.ts`, one per use case — no `?action=` dispatch. They are **request-driven**: inputs come from the query string / JSON body, NOT from SDF script parameters. SDF objects live in `src/Objects/restlet/*.xml`.
- **Response:** every endpoint returns `ApiResponse<T>` (`{ success, data, message, error }`) via the `success()` / `failure()` helpers in `shared/response.ts`. User-facing `message` strings are in Spanish.
- **Logging:** use `N/log`, never `console` (Biome `noConsole` is an error).
- **Biome (strict, differs from defaults):** `noExplicitAny`, `noConsole`, `noDoubleEquals` are errors; `lineWidth: 100`, single quotes, semicolons, trailing commas. `organizeImports` is OFF for `src/TypeScripts` (preserve manual import order).
- **Language:** identifiers and code in English; existing comments mix ES/EN — match the file you're editing.

## Domain modeling pattern

Not everything in `domain/` must be a class. Each feature uses the piece type that fits (details and diagrams: `docs/arquitectura/patron-dominio.md`):

1. **Entity** — identity + rules over its own state: `XxxProps` (readonly), class with private readonly props, getters, `isX/hasX/canX` methods, `toJSON(): XxxJSON`. E.g. `Customer`.
2. **Domain calculation** — pure functions with explicit input/output types, no identity; inject the reference date for determinism. E.g. installment amortization.
3. **Read model** — projection composing other features: reuse their `XxxJSON` types (`Pick`/`Omit` allowed), no duplicated shapes, no rules. E.g. sales-order summary.

Conventions: `I` prefix ONLY for ports (`IXxxRepository`); the domain owns `XxxProps`/`XxxJSON`, the use case owns `XxxInput`/`XxxOutput`; file order is constants → types → entity → pure functions; business rules live in the domain, not in use cases; every domain has a domain test; zero `N/*` imports and no NetSuite field names (comments included).
